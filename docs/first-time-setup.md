# ตั้งรหัสผู้ดูแลชั่วคราวผ่านหน้าเว็บ

**สำหรับ staging ที่จำกัดการเข้าถึงเท่านั้น** บัญชีหมดอายุ 24 ชั่วโมงหลังตั้งค่า; CRM ยังเป็นเดโมและยังไม่เชื่อม MySQL/บัญชีจริง ไม่ใช้ข้อมูลลูกค้าหรือ token LINE จริง ระบบยังไม่มีการจำกัดจำนวนครั้งล็อกอินและไม่ได้ตรวจสิทธิ์ทุก action ครบ จึงต้องให้ผู้ดูแลโฮสต์จำกัด IP/VPN และตั้ง rate limit ก่อนเปิดใช้งาน ห้ามเปิดหน้า setup บนอินเทอร์เน็ตทั่วไป

## ขั้นตอนสำหรับผู้ดูแลโฮสต์

1. นำโค้ดเวอร์ชันที่มี `web/scripts/init-setup.cjs` และหน้า `/setup` ขึ้น staging แล้วติดตั้งและ build ใน `web` (`npm ci` และ `npm run build`) ตั้ง HTTPS และจำกัดการเข้าถึงด้วย VPN/IP allowlist
2. ตรวจว่า Plesk **Application Root** เป็นโฟลเดอร์ `web` ที่มี `package.json` และ **Document Root** เป็น `web/public` ไม่ใช่ `web` หรือ `web/data` เพื่อป้องกันการดาวน์โหลดไฟล์ข้อมูลลับ ตรวจสอบจริงว่า `/data/private/setup.json` ไม่สามารถเปิดจากเว็บได้ก่อนใช้ฟีเจอร์นี้
3. ใน Terminal ของโฮสต์ ภายใน `web` รัน:

   ```bash
   node scripts/init-setup.cjs
   ```

   จะเห็นรหัสตั้งค่าครั้งเดียว หมดอายุใน 15 นาที **อย่าส่งรหัสหรือภาพหน้าจอในแชท** เครื่องมือนี้สร้างไฟล์ `web/data/private/setup.json` แบบสิทธิ์เจ้าของเท่านั้น และไม่ overwrite ไฟล์ที่มีอยู่ เก็บไฟล์และ terminal output ให้พ้นจากผู้ใช้คนอื่นและ backup/log สาธารณะ
4. เปิด `https://<โดเมน staging>/setup` กรอกรหัสตั้งค่าที่แสดงและรหัสผ่านใหม่อย่างน้อย 16 ตัวอักษร/ไม่เกิน 72 ไบต์ ยืนยันรหัสผ่าน แล้วกดบันทึก
5. เปิด `/login` ใช้ชื่อผู้ใช้ `admin` และรหัสผ่านที่ตั้งไว้ บัญชีนี้เป็น **ผู้ดูแลชั่วคราว 24 ชั่วโมง** ไม่ใช่บัญชีจริง เมื่อหมดเวลา session จะใช้ไม่ได้
6. หลังทดสอบ ปิดการเข้าถึง staging และให้ผู้ดูแลลบไฟล์ `web/data/private/setup.json` อย่างปลอดภัย แล้วตรวจว่าบัญชีเข้าไม่ได้ การลบไฟล์ทำให้ session ที่อาศัยไฟล์นี้ใช้ไม่ได้; อย่าลบไฟล์หรือ directory อื่น ไฟล์นี้ไม่ได้อยู่ใน Git

หากตั้งไม่ทันใน 15 นาที หรือคำสั่งแจ้งว่ามี setup อยู่แล้ว ให้ผู้ดูแลตรวจสถานะและปิดการเข้าถึงเว็บก่อน หากยืนยันว่าต้องการยกเลิก setup/บัญชีชั่วคราวเดิม จึงลบ **เฉพาะ** `web/data/private/setup.json` แล้วรันคำสั่งอีกครั้ง รหัสและ session เดิมจะใช้ไม่ได้ อย่าลบไฟล์ `setup.lock` ขณะมีคำขอทำงานอยู่ หากเครื่องล่มระหว่างตั้งค่าและ lock ค้าง ให้ผู้ดูแลหยุดแอป ตรวจสอบก่อนลบ lock เท่านั้น

การตั้งค่านี้ต้องใช้ดิสก์ที่เขียนได้และคงอยู่ร่วมกันระหว่าง process; ไม่รองรับ filesystem ชั่วคราวหรือหลายเครื่องที่ไม่แชร์ไฟล์ การอ่าน/เขียนผิดพลาดจะปฏิเสธการตั้งค่า

**ยังไม่ได้ทดสอบบน Plesk จริง** หาก POST กลับ 403 ตรวจ origin/host/proxy และ Plesk logs; 403 ที่พบก่อนหน้านี้ยังไม่ได้ระบุสาเหตุ อย่าปิดระบบป้องกันทั้งหมดโดยไม่ตรวจสอบ

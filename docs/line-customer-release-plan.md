# แผนทำบริการลูกค้าผ่าน LINE และเผยแพร่

## สถานะปัจจุบัน

หลังบ้าน Next.js ใช้ข้อมูล CRM เดโม JSON; สินค้า/บริการและโปรโมชั่นมีหน้าจัดการเดโม, Rich Menu รองรับ 6 ช่อง 3×2 และกำหนด URL/ข้อความ แต่ยังไม่ยืนยัน LINE account จริง หน้าลูกค้าสำหรับสินค้า โปร จอง สมาชิก/คะแนนยังไม่ได้เชื่อมผ่าน Rich Menu และระบบคะแนน/QR ยังไม่มี หน้าหลังบ้าน `/line-workspace` เป็นแผนและทางลัด ไม่ใช่ระบบลูกค้าที่เปิดใช้งานแล้ว

## ขั้นตอนและเกณฑ์ผ่าน

1. **สำรวจและเชื่อมข้อมูลเดิม** — ขอ schema ตารางเดิมแบบไม่รวมข้อมูลส่วนบุคคล ตรวจ auth, บัญชี, สินค้า, โปร, งาน/บิล; พัฒนา repository กับ MySQL เดิมโดยไม่เปลี่ยน schema หรือย้ายข้อมูลโดยไม่ได้รับอนุมัติ ทดสอบสำเนาฐานและ backup/restore
2. **สินค้า/บริการและโปรลูกค้า** — ระบุสินค้า/ราคา/สิทธิ์ที่เปิดเผย สร้างหน้าลูกค้าแบบ mobile และทดสอบโปรตามวันเวลา; หน้าหลังบ้านที่ต้องล็อกอินไม่ใช่ URL สำหรับลูกค้า
3. **นัดหมาย** — ออกแบบและพัฒนาฟอร์มลูกค้า กติกาวันเวลา การยืนยัน การยกเลิกและการป้องกันสแปม เชื่อมคิวศูนย์บริการที่ทดสอบ transaction แล้ว
4. **สมาชิกและคะแนน** — ร้านอนุมัติกติกาสะสม/แลก/คืน/หมดอายุ; ตรวจว่า schema เดิมรองรับ ledger/QR/audit หรือไม่ หากไม่รองรับให้เสนอทางเลือกและขออนุมัติก่อนเปลี่ยนแปลง พัฒนายืนยันตัวตน, ป้องกัน QR ซ้ำและบิลซ้ำ, audit, privacy และทดสอบ transaction
5. **สร้าง Rich Menu** — ใช้บัญชี LINE ทดสอบ ตั้ง 6 ช่อง โปรโมชั่น / สินค้า / จอง / สมาชิก / Google Maps / ติดต่อ ตรวจภาพ 2500×1686 ให้ตรงผัง 3×2, ตรวจลิงก์ลูกค้าและทดสอบบนมือถือจริง Google Maps และข้อมูลติดต่อรอเจ้าของร้านยืนยัน
6. **วางแผนเผยแพร่** — จัดทำข้อความ ภาพ ช่องทาง วันเวลา ผู้อนุมัติ และวิธี rollback; ทดสอบผล LINE/Facebook, idempotency และการรายงานสถานะ ปัจจุบันไม่มี scheduler ที่ยืนยันว่าทำงานจริงและ metrics เป็นข้อมูลจำลอง
7. **เปิดใช้งานจริงเมื่อผ่าน UAT** — ตรวจ HTTPS, secrets, role ทุก API/action, นโยบายข้อมูลส่วนบุคคล, backup/restore, monitoring, ผลส่งและแผนยกเลิก ก่อนเจ้าของอนุมัติเปิดจริง ห้ามใส่ token จริงในระบบเดโม

## สิ่งที่ต้องตกลงกับร้าน

- ลิงก์ Google Maps และช่องทางติดต่อ/เวลาให้บริการ
- กติกาแต้มและรางวัล, ผู้มีสิทธิ์ปรับแต้ม, แนวทางยืนยันสมาชิก LINE
- รายการสินค้า/ราคา/โปรที่อนุญาตให้ลูกค้าเห็น และวัน/ผู้อนุมัติเผยแพร่
- schema เดิมแบบปิดบัง secrets/ข้อมูลส่วนบุคคล และสภาพแวดล้อม staging ที่แยกจาก production

หน้าตั้งค่าปัจจุบันแสดงสถานะและทางลัด ยังไม่เก็บ credentials หรือเปลี่ยนการตั้งค่า server ผ่านเว็บ และสถานะ "มีค่า token" ไม่ได้ตรวจสิทธิ์หรือยืนยันการเชื่อมต่อ

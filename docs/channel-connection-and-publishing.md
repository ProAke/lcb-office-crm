# สถานะการเชื่อมช่องทางและการเผยแพร่

## สิ่งที่เปลี่ยน

- หน้าตั้งค่าสำหรับ admin มีปุ่มทดสอบ LINE (GET bot info) และ Facebook Page (GET page ID) โดยใช้ token ที่ผู้ดูแลกำหนดไว้บนเซิร์ฟเวอร์เท่านั้น ไม่ส่ง token หรือ response body ไปยัง browser การทดสอบสำเร็จหมายถึง API ตอบรับการอ่าน ไม่ยืนยันการส่งข้อความ/โพสต์หรือ webhook
- การกดส่งจาก Publishing Hub ต้องเป็น admin และเลือกยืนยันก่อนส่ง สถานะแยกแต่ละช่องทาง: ไม่ตั้ง token/ไม่รองรับเว็บ = ไม่ส่ง; HTTP สำเร็จ = API รับคำขอ (ไม่ใช่ยืนยันถึงลูกค้า); HTTP error = ไม่สำเร็จ; network timeout/error = ผลไม่แน่ชัด ต้องตรวจปลายทางก่อนส่งซ้ำ
- การกดปุ่มที่การ์ดโปรโมชันสร้าง **ร่าง** เท่านั้น ไม่ได้ส่งออกหรือเปิดโปรให้อัตโนมัติ
- ไม่สร้างสถิติสุ่มใน production และ cron insights ใน production คืน 501 เพราะยังไม่ได้พัฒนาการดึงข้อมูลจริง ข้อมูล seed/สถิติเดิมยังเป็นเดโม

## ข้อจำกัดและข้อควรระวัง

- ระบบ CRM และประวัติโพสต์ยังใช้ JSON store เดโม เขียนล้มเหลวอาจไม่ถูกรายงาน ไม่มี transaction, idempotency หรือ durable queue จึง **ยังไม่พร้อมใช้ส่งข้อความจริง/ข้อมูลลูกค้าจริง**; ปุ่มทดสอบให้ใช้ test account เท่านั้น
- UI ยังไม่บันทึก/เปลี่ยน token ผ่านหลังบ้าน และยังไม่มี secret manager ต้องวางแผน RBAC, audit, encryption-at-rest, rotation และที่เก็บที่ปลอดภัยก่อนทำฟีเจอร์ดังกล่าว อย่าใส่ token ใน Git/chat
- ผลลัพธ์ network error อาจเกิดหลังผู้ให้บริการรับคำขอแล้ว อย่าส่งซ้ำก่อนตรวจ LINE/Facebook; สถานะเดิมจาก seed หรือรุ่นก่อน **ไม่ใช่หลักฐาน** ว่าส่งจริง
- การตั้งค่า `DATABASE_URL` ไม่ได้เชื่อม CRM กับฐาน MySQL เดิม ต้องตรวจ schema จริงและพัฒนาชั้น repository/auth โดยไม่เปลี่ยน schema หรือย้ายข้อมูล
- ปุ่มทดสอบยังไม่ได้ทดสอบกับ LINE/Facebook จริง; ไม่มีการเปิดใช้งาน scheduling, webhook delivery guarantees, analytics หรือระบบสมาชิก QR ในงานนี้
- ต้นแบบยังต้องทบทวนสิทธิ์ทุก Server Action/API, CSRF, rate limit, ตรวจล็อกอินจริง, privacy และป้องกันการส่งซ้ำก่อน production

การเปลี่ยนแปลงนี้ไม่ตั้งค่า secrets ไม่ deploy และไม่เปลี่ยนฐานข้อมูล ปรึกษา [แผนเผยแพร่](line-customer-release-plan.md) สำหรับลำดับงาน
